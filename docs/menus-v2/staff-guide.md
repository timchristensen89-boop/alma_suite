# Alma Menus — how it works for the team

One place for every menu at Alma Avalon and St Alma: the food menu on the website and the printed A4, the drinks book, the functions pack, the table cards (happy hour, bottomless, specials), the What's On listings, and private-event menus. Edit here; the website and the printed PDF follow.

## Who can do what

- **Anyone with Menus access** can open a menu, start or continue a draft, type and rearrange dishes, see the live preview, and edit a promotion's listing and photo.
- **Managers and the head chef** (and anyone given the "Publish menus" toggle in the Staff app) also publish, add new menus and promotions, rename, archive, hide and end.

## The home

Each venue's menus are grouped by kind: Food, Drinks, Functions, Promotions, Private events. A card shows what the page is headed, the page format (A4 or A5, how many pages), what is live and who last edited. Use the search box and the Kind / Status filters when the list is long ("Draft in progress", "Events coming up", "Past events").

- **New menu** on a venue heading: pick the kind, give it a name, choose whether to start empty or as a copy of another menu (a Tuesday menu usually starts as a copy of the à la carte). A private-event menu also takes the event's name, date, organiser reference and guest count — internal details that never print.
- **Rename / Menu details**: the name on the home, whether the menu is public (served to the website) or private, the event details. The website link name is fixed when the menu is made and never changes, so renaming is safe.
- **Archive**: takes a menu off the home. Its history and PDFs stay; a publisher can unarchive it. Nothing is ever deleted.

## The editor

Left: the content. Right: the page exactly as it prints — every page, updated as you type. Saving is automatic.

- **Title block**: the printed heading (blank prints the template's own title), and on cards and books the subheading, the when-line, the headline price and the conditions. On a promotion's card these three come from the promotion and are shown read-only — edit them on the promotion so the website and the card never disagree.
- **Pages** (drinks books, functions packs, two-page cards): the strip shows each page and how full it is. Press a page to edit it on its own; add or remove pages. Each section says which page it prints on.
- **Sections**: standard (name, dietaries, price, description), priced header (names only, one price for the group), set menus, text block, list, price table (several columns, e.g. 150 mL / 250 mL / bottle), course (for event menus). Drag to reorder. Hide a section or a dish ("86") instead of deleting it if it is coming back.
- **Dishes**: dollars with cents ("12.50"), a small qualifier (ABV, region, "with a set menu"), a note, dietary codes, seafood origin, and the marks (staff pick, limited, on tap, new). The dietary legend at the foot is generated from the codes in use.
- **Checks**: errors (a seafood dish without an origin, a page that overflows) block publishing; warnings (a dish without a price) are shown and can be accepted.
- **Publish…**: shows the checks, how full each page is, and every change since the live version. Publishing renders the PDF; the website picks up a public menu within five minutes.
- **History**: every published version with its PDF, diffs between versions, restore an older version as a new draft, and the audit trail.

If two people edit the same draft, the second save is refused with "Reload their changes" and nothing typed is lost. If a menu is archived while you are in it, the editor goes read-only and keeps your unsaved edits in that browser to apply later.

## What's On (promotions)

A promotion is one record: the website listing (title, description, day and time, weekdays and start time for the booking button, dates, price, conditions, photo) and, if it prints, its A5 card. The time line, price and conditions are typed once and used by both.

- **New promotion** (publishers): name, website title, and whether to make a new card, link an existing card, or have no card.
- **Edit the listing**: the right-hand column shows the listing as the website will receive it, as you type. Press **Save**. A promotion with unsaved changes says so; the website keeps what was last published.
- **Publish…**: lists what the website will see change and what happens to the card — if the card has a draft it is published in the same step; if the card's live PDF is behind the promotion's price or times it is reprinted. If the card cannot be published, nothing is: the website never shows a listing whose PDF disagrees with it.
- **Hide** takes a promotion off the website without losing its publication; **Show** puts it back; **End** retires it (it can be shown again). A promotion with an end date drops off the website by itself the day after.
- **Photo**: landscape, a few hundred KB. Replacing a photo keeps the old one on earlier publications.

## Private events

A private-event menu is private by default: the team can print it and open it from History, but it is never served to the website, not even by a direct link. Start one from a template (the venue's A5 card), as a copy of a past event, or empty; give it the event's name, date and guest count; use **Course** sections (a lead-in like "Choose one", the dishes, a note), and turn **Show prices** off. Duplicate it for the next event from New menu → Start from.

## Imported menus

The reference menus (drinks books, Tuesday, the table cards, the functions pack, the set-menu pack) and the website's current What's On events were imported as drafts. They are starting points, not approved content: open each one, work through the review notes in the import inventory (hours that disagree between sources, prices that moved, wording the template cannot carry), and publish only when it is right.
